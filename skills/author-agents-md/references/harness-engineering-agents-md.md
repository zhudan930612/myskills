# AGENTS.md 官方要求提炼

本文档提炼自 OpenAI 官方文章 `Harness engineering: using Codex in an agent-first world` 中与 `AGENTS.md` 相关的要求。

## 核心判断

1. `AGENTS.md` 应该是地图，不应该是手册。
2. 仓库应作为智能体可读取知识的记录系统。
3. 应使用渐进式披露：先给小入口，再引导去更深的文档。
4. 稳定知识应从聊天和人脑迁移到版本化仓库文件。
5. 高频重要规则应逐步沉淀为 lint、CI、脚本或其他检查器。

## 为什么“大 AGENTS.md”会失败

- 上下文是稀缺资源，超长指令文件会挤占任务、代码和关键文档的空间。
- 当所有内容都显得重要时，真正重要的内容就失焦了。
- 大手册很容易腐烂，最终变成陈旧规则堆积地。
- 单个大块文本很难机械校验新鲜度、所有权和交叉链接。

## 好的 AGENTS.md 应该是什么样

- 一个短小的入口文件，约 100 行是经验量级，不是硬指标。
- 清晰指向架构、计划、产品规格、参考资料和运行规则。
- 对大领域优先指向索引文档，而不是一次性展开全部细节。
- 复杂工作应有版本化执行计划和决策记录。
- 文档维护最好有 lint、CI 和定期清理机制支撑。

## 对生成和审查的直接含义

- 详细内容应进入专门文档，不应堆在 `AGENTS.md`
- `AGENTS.md` 应聚焦在定位、路由和硬约束
- 优先引用仓库内 Markdown、schema、脚本和命令
- 如果某条规则重复出错，要么指向 owner doc，要么建议做成检查器

## 推荐关注的 section

- 仓库目的
- 仓库地图
- source of truth
- 工作闭环
- 验证命令
- 硬约束
- out of scope
