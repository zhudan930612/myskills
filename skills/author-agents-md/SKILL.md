# 生成与审查 AGENTS.md

这个技能只做两件事：

1. 根据 OpenAI 官方 `harness engineering` 文档要求生成 `AGENTS.md`
2. 审查现有 `AGENTS.md` 是否符合该文档要求

核心原则：`AGENTS.md` 应该是给智能体看的简洁导航图，不是大而全手册。仓库本身才是记录系统，详细内容应落在版本化文档、脚本和校验器里。

## 适用场景

- 用户要求新建 `AGENTS.md`
- 用户要求重写、收敛、瘦身 `AGENTS.md`
- 用户要求检查 `AGENTS.md` 是否符合 OpenAI 官方建议
- 用户要求指出 `AGENTS.md` 的问题并给出修订建议

## 不要这样做

- 不要把 `AGENTS.md` 写成百科全书
- 不要把大量产品、架构、流程细节直接堆进 `AGENTS.md`
- 不要把只存在于对话、会议纪要、聊天工具里的稳定规则直接写进 `AGENTS.md`，除非先沉淀到仓库文件
- 不要保留无法指向具体文件、命令或检查器的空泛要求

## 任务一：生成 AGENTS.md

执行顺序：

1. 查看仓库根目录、现有顶层文档和关键脚本
2. 找出真实的 source of truth：
   - 架构文档
   - 产品/需求文档
   - 计划文档
   - 质量与验证入口
   - 安全或可靠性约束
3. 如果缺少关键文档，明确记录 gap；不要靠把 `AGENTS.md` 写长来补
4. 生成一个简短的 `AGENTS.md`，通常控制在约 60 到 120 行
5. 每条重要规则尽量落到以下一种锚点：
   - 一个版本化文档
   - 一个脚本或命令
   - 一个 lint / CI / checker
   - 一个有稳定路径的本地约定文件

生成时优先使用下面这类结构：

- 仓库目的
- 仓库地图
- 事实来源
- 工作闭环
- 硬约束
- 不应写在这里的内容

## 任务二：审查 AGENTS.md

审查时按下面清单逐项检查：

1. 它是不是“地图”而不是“手册”
2. 是否明确告诉智能体下一步该去哪个文件看细节
3. 主要规则是否都能指向真实文件、命令或检查器
4. 是否重复了本应由 deeper docs 持有的长内容
5. 是否依赖未落盘的人类记忆或外部聊天上下文
6. 是否缺少架构、产品、计划、验证这些高频入口
7. 是否存在陈旧、无法校验或无 owner 的规则

审查输出应包含三部分：

1. 结论：通过 / 不通过 / 部分符合
2. 问题清单：按严重度列出
3. 修订建议：指出应迁移到哪里、补什么链接、补什么校验

## 生成与审查标准

- `AGENTS.md` 应短、平、快，可快速扫描
- 以项目路径和命令为主，少写抽象口号
- 优先指向索引文档，不要一次性展开所有叶子文档
- 详细规则应回到版本化文档，而不是留在 `AGENTS.md`
- 如果某条规则经常出错，应建议把它进一步变成脚本、lint 或 CI 检查

## 默认输出要求

如果是“生成”任务，输出：

1. 新的 `AGENTS.md`
2. 缺失信息清单
3. 可选的后续治理建议

如果是“审查”任务，输出：

1. 审查结论
2. 问题清单
3. 建议修改后的结构或改写方向
